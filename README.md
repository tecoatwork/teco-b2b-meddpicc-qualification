# MEDDPICC商机判断与推进：思路与使用方法

Copyright (c) 2026 tecoatwork

## 解决什么问题
用MEDDPICC检查复杂B2B商机的价值、决策链、采购流程与推进缺口，制定可验证的下一步。本Skill把分析落实为可验证的问题、客户沟通或具体动作，不以成交保证作为输出。

## 理论是什么
MEDDPICC是商机资格与推进框架：Metrics可衡量价值、Economic Buyer经济决策人、Decision Criteria决策标准、Decision Process决策流程、Paper Process合同及手续流程、Identify/Implicate Pain识别并理解痛点、Champion内部推动者、Competition竞争选择。不同体系对I的展开略有不同，这里同时检查问题及其影响。

[理论来源](https://meddicc.com/meddpicc-sales-methodology-and-process)。以下步骤和案例为外贸场景的原创应用解释，不代表原作者逐字表述。

## 先准备哪些资料
客户及联系人；销售阶段；实际沟通与日期；当前方案报价；已知评估标准和采购流程；参与角色；竞争或现有方案；时间约定与我方限制。

优先提供客户实际原话、发生时间和我方真实条件。公司类型与职位只能支持初步假设；已有客户记录应优先于一般行业印象。可以提供相关笔记路径，读取失败时应说明，不能假装读过。

## 完整分析方法

### 第1步：判断使用深度

复杂项目、多角色采购使用八项；简单补货仅检查影响当前订单的项。信息缺失代表未知，不自动等于差商机。

本步完成标准：形成一个有依据的判断或明确的待验证项，并知道下一步需要什么信息。无法确认时保留未知，不为进入下一步而补造答案。

### 第2步：建立证据表

八项逐项标注已确认／推断／未知／不适用，附客户原话、来源和时间。不编造成交概率，也不凭空设置评分权重。

本步完成标准：形成一个有依据的判断或明确的待验证项，并知道下一步需要什么信息。无法确认时保留未知，不为进入下一步而补造答案。

### 第3步：核实角色

经济决策人关注预算和最终经济批准，签字人未必相同。Champion需有影响力、利益相关且有实际内部推动行为；回复积极不等于内部推动者。

本步完成标准：形成一个有依据的判断或明确的待验证项，并知道下一步需要什么信息。无法确认时保留未知，不为进入下一步而补造答案。

### 第4步：拆开流程

决策流程回答如何选择和批准；手续流程回答选定后如何完成合同、准入、法务或建档。具体企业可能交叠，按实际记录，不假定固定顺序。

本步完成标准：形成一个有依据的判断或明确的待验证项，并知道下一步需要什么信息。无法确认时保留未知，不为进入下一步而补造答案。

### 第5步：找关键缺口

优先找阻止下一步发生的1—3个缺口，写明要向谁核实、需要什么证据、谁负责和何时回看。包含客户维持现状、推迟项目或内部自制等竞争选择。

本步完成标准：形成一个有依据的判断或明确的待验证项，并知道下一步需要什么信息。无法确认时保留未知，不为进入下一步而补造答案。

## 外贸演示案例

模拟：产品开发人员认可样品，但说“采购还要讨论”。不能判定即将成交。应确认样品验收是否完成、采购还比较什么、谁批准预算、是否需要供应商建档，再建议提供对应资料。

以上是教学模拟，不是已发生的交易、真实客户回答或产品性能证明。实操时用当前客户资料替换，引用来源，不直接复制成事实。

## 最终交付与用途

商机状态摘要；MEDDPICC八项证据表；关键卡点及验证问题；推进清单（动作｜负责人｜建议时间或触发条件｜完成证据｜客户是否确认）。

内部分析用于判断和准备；对客稿用于人工审核后沟通。清单中的负责人、时间及动作如未经双方确认，标注“建议”，不能写成双方约定。客户回复后更新相关判断，不把旧结论长期当作事实。

## 证据如何处理

| 信息状态 | 写法与处理 |
|---|---|
| 客户明确回答 | 保留原话或准确转述、日期与上下文 |
| 我方确认的能力与权限 | 标注资料版本或授权来源，不扩大适用范围 |
| 公开资料 | 链接、发布日期或查询日期；企业自述仍标注自述 |
| 分析假设 | 说明依据、替代解释及验证问题 |
| 缺少资料 | 写待确认，并指出缺口是否影响当前行动 |

## 如何与已有工作流配合

需求不清交给SPIN；出现具体异议交给异议处理Skill；根据已确认推进节点交给跟进Skill。

这些衔接是使用建议，不要求安装其他Skill才能运行。避免重复调研；把已确认资料、未决问题、来源和下一步一起交接即可。

## 可直接借鉴的沟通问题

根据客户已提供的信息选择使用，不要一次问完。涉及我方方案变化的表达只有在实际可执行时才能使用。

| 目的 | 示例表达 |
|---|---|
| 价值 | 改善这个问题，对项目最重要的结果是什么？ |
| 决策标准 | 评估除了价格，还会重点比较哪些方面？ |
| 决策流程 | 样品评估通过后，通常还需要哪些团队参与？ |
| 手续 | 正式下单前，需要我们准备哪些供应商资料？ |

## 常见误区

把联系人当决策人；把热情当Champion证据；填满表格就声称高胜率；把预计时间写成客户承诺；把审批和合同手续混在一起；忽视不采购的可能。

## 如何判断结果是否可用

- 判断能否追溯到资料，假设是否明确标注？
- 是否选出了当前最重要的缺口，而非堆砌所有可能问题？
- 对客表达是否自然，并且只有一个清晰的本轮下一步？
- 是否超出了我方能力、授权或客户联系约定？
- 一线销售能否看完就知道该问谁、准备什么、做什么？

## 边界场景自检

联系人频繁回复但无法影响内部评估：不能认定Champion。客户口头说满意：不能写成测试通过或订单确认。

这些是使用前的人工检查情境，并非已经完成跨模型或真实销售效果测试。
